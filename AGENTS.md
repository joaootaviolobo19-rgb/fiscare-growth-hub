## Application structure

- Keep the Fiscare landing page assembled from focused section components, with shared brand and CTA controls, so section changes remain isolated.
- Keep editable landing copy — services, FAQ groups and the social-proof phrases — in `src/lib/landing-content.ts`, so the page and its tests read from one source. The social-proof section only shows Fiscare's own promise phrases; never attribute quotes, names, numbers, prices or deadlines to clients.
- Keep diagnosis schemas in the browser-safe shared module (`src/lib/diagnosis.ts`); any connected receiving server must revalidate the same schema to prevent invalid submissions.
- Diagnosis leads are delivered through EmailJS using the public template ids in `.env`; the transport (config check, retry and timeout) lives in `src/lib/emailjs.ts`, and `DiagnosisForm.tsx` only keeps the validation boundary. The template is `emailjs/template-diagnostico.html`. The eleven payload keys (`nome`, `whatsapp`, `email`, `empresa`, `cnpj`, `possui_cnpj`, `ramo`, `areas`, `mensagem`, `consentimento`, `enviado_em`) must stay in sync with the EmailJS template — adding a field here without adding `{{field}}` there silently drops it from the e-mail. Set the template's "Reply To" to `{{email}}` so replying reaches the visitor.
- The CNPJ field is optional on purpose and must never block the e-mail: the mask and check digit live in `src/lib/cnpj.ts` and only produce an on-screen hint. A visitor without a CNPJ ticks "Ainda não tenho CNPJ" and the lead carries "Ainda não possui CNPJ".
- The three form steps stay lean: step 1 collects name, WhatsApp and e-mail (all required, e-mail included), step 2 companies specifics with the optional CNPJ, step 3 needs, message and LGPD consent. Validation moves focus to the first invalid control, and inputs keep `name`/`autoComplete` so browsers fill them.
- Keep the delivery path fault tolerant: retry network/5xx failures, time out each attempt, never clear the fields on failure, never write the lead to storage, and log only a status code (no PII).
- Keep privacy and terms in dedicated public content routes with independent metadata so footer links are usable and shareable, and keep their copy in sync with what the form actually does with data.
- Keep the WhatsApp number and its prefilled message templates in `src/lib/contact.ts`, and build every URL through `whatsappLink()` so the number changes in one place. The page exposes WhatsApp in exactly two places — the floating button and the number in the footer — plus the exit offer; the owner asked for that restraint, so do not add WhatsApp links to the header, hero, sections, service cards or the form. The diagnosis form stays the primary CTA, and the exit offer shows once per session and only on pointer/fine viewports already wide enough for the desktop layout. Below 481px the floating button is icon-only so it does not cover the form fields.
- Keep motion in the shared controls (`Reveal`, `RevealWords`, `Magnetic` in `shared.tsx`), the pointer spotlight hook (`src/lib/pointer-glow.ts`) and the hero/services parallax, guard every animation with `useReducedMotionSafe()` (`src/lib/use-reduced-motion-safe.ts`) — never `useReducedMotion()` directly, because it flips after hydration and React swaps the whole tree — and keep the hero entrance in CSS so the headline renders with or without JavaScript.
- The page opens with a CSS-only brand curtain (`IntroCurtain.tsx`) whose panels split to reveal the hero. It must play without JavaScript, never capture pointer events, and disappear completely under reduced motion; its timeline lives in `styles.css` and is timed so the hero starts as the panels open.
- The hero and services sections share the decorative SVG scene in `FinanceBackdrop.tsx` (line chart kept as the signature, dot world map, data ticks, guilloche arcs, candlesticks over volume bars, dial). It is `aria-hidden`, never blocks clicks, and is positioned behind the content with scroll parallax; it must not overlap text at strengths that hurt readability. Under 768px the landscape artwork is replaced by the compact scene (`.fb-scene-mobile`, 390×820) so the motifs are not cropped into noise, and the services band runs quieter than the hero.
- Social proof comes before services in `src/routes/index.tsx`, so the promise reads before the catalogue.
